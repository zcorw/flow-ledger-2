# 每日开销与网页 OCR

访问 `/expenses` 或左侧“每日开销”。本轮是用户追加的消费记录功能，独立于既有资产快照和债权债务。项目品牌和原有资产统计口径保持不变。

## 使用与边界

- 手工录入、编辑和删除开销；金额、币种、消费日期必填，分类默认“未分类”，可逐笔修改。商户、支付账户和备注可选。
- 日期范围、币种及分类可组合筛选；列表每页 50 笔，汇总覆盖整个筛选范围。按币种、按日与币种、按分类与币种分别汇总，不跨币种相加。
- 仅记实际消费。转账和信用卡还款不应再记为消费；本轮没有退款冲销、预算、报销、账户余额扣减或实时总账。
- “返回”保留当前页面内的草稿；关闭浏览器或离开该功能不持久化草稿和原图。

## 保存和数据结构

新增 `expenses` 表，迁移 `0010_daily_expenses`。金额在 PostgreSQL 使用 `numeric(20,6)`，开发 SQLite 使用固定小数文本，避免 SQLite NUMERIC 的浮点精度损失。API 和汇总使用 Decimal，前端以字符串传递、格式化金额。

消费日期是 `YYYY-MM-DD` 的日历日期，不接受时间戳或隐式时区换日。所有接口复用现有 session 认证，并按 `user_id` 限定记录、关联账户和汇总；增改删写入审计。

新增接口：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/expenses` | `startDate/endDate/currency/category/offset/limit` 筛选、列表与汇总 |
| `GET /api/v1/expenses/accounts` | 当前用户可关联账户 |
| `POST /api/v1/expenses` | 新增；需 UUID `requestKey`，来源为 `manual` 或 `receipt_ocr` |
| `PUT /api/v1/expenses/{id}` | 修改可编辑字段 |
| `DELETE /api/v1/expenses/{id}` | 从开销记录和汇总中移除 |

每个录入草稿复用同一请求键；数据库唯一约束 `(user_id, request_key)` 保证并发重试只生成一笔。相同键和不同内容返回 409，避免静默覆盖。删除保留幂等墓碑，延迟重试不会重建记录。疑似重复按同日、币种、金额、商户提示 409；用户明确选择“确认仍保存”后可录入合法相同消费，不自动合并。

备份格式升级到版本 2，显式加入开销表和恢复顺序；保留金额、来源、分类、请求键和删除状态。可恢复没有开销表的版本 1 备份；作为全量恢复，这会清空当前开销，恢复为旧备份的状态。恢复仍沿用原有重认证、预备份和事务。

迁移检查还发现旧迁移 `0003` 已存在的汇率索引 `idx_fx_rates_currency_date` 未登记在 ORM；只补了模型元数据以匹配旧迁移，没有删除索引或修改历史迁移。

## OpenAI 图片识别

收据识别已切换到后端 OpenAI Responses API，默认模型 gpt-6-luna。图片会发送给 OpenAI，不能再视为本地离线处理。保留人工核对和单笔候选流程，分类由用户选择。配置、费用、隐私、限制和测试边界见 [OpenAI 收据识别](10-openai-receipts.md)。旧版本地 OCR 的验证仅作历史记录。
