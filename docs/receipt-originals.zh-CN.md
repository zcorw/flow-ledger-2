# 单据原图存储

[English](receipt-originals.md) | **简体中文**

执行迁移 `0013_receipt_originals` 并部署两端后，新上传的有效 JPEG、PNG、WebP 会作为私有二进制附件保存在 PostgreSQL。现有 VPS 数据库持久卷使其在容器替换后继续保留，不创建公开图片目录。此前没有保存的照片无法补回。

一并保留原始字节、MIME、大小和 SHA-256。原图可能含 EXIF 等元数据；只有另行生成的识别副本会纠正方向、移除元数据并转换 JPEG。仍限制 8 MiB、2000 万像素及单边 10000 像素，拒绝动画图片。有效原图先提交保存再调用识别；识别失败保留原图和经过筛选的失败码，无效图片不归档。

单据是独立的识别候选记录，未知字段留空，不自动创建开销。识别 JSON 保持原有格式，另通过响应头 `X-Receipt-Id` 返回单据标识。网站从 **每日开销 → 识别单据** 访问，可查看私有原图并明确选择记录开销。开销用 `receiptId` 关联，禁止重复关联。删除开销不删除原始单据；退出眼镜或取消请求也不会删除服务端已保存的原图。

`GET /api/v1/receipts`、`/{id}`、`/{id}/image` 需要所属用户的网页登录会话。收据识别设备令牌不能浏览归档或创建开销。原图响应设置私有、不缓存及 nosniff，并校验 MIME。数据库错误隐藏 SQL 参数，审计日志不写图片字节。

PostgreSQL 定时和部署前备份自动包含原图及关联。存在单据时，网页 JSON 备份使用版本 3，将原图编码为 base64，恢复时校验哈希；仍支持旧版本 1/2。网页导出和上传包含图片后上限为 64 MiB，更大的归档使用服务器全量备份。恢复前先备份，再在事务中替换关联记录。降级 0013 会删除原图和关联，回滚前应保存全量备份。

验收需覆盖原图哈希不变、账号隔离、字段不全或识别失败、开销关联、备份恢复、VPS 容器替换及最新眼镜资源包。自动化测试使用合成图片和替代识别服务，不使用生产照片或付费识别。
