## 覆盖的行为

- Decimal 最大金额与 6 位小数、非法范围、多币种分别汇总、闰日和非法日期、时间戳及非标准日期拒绝。
- session 认证、跨用户记录和账户隔离、增改删和审计、已有资产快照统计保持不变。
- 同一请求的并发 4 次提交只生成一笔和一条创建审计；同键不同内容冲突；删除后旧请求不重建；合法同额消费需确认后可保存。
- 备份版本 2 往返一致、版本 1 旧备份兼容、恢复后请求重放仍幂等。
- 桌面与 390×844 移动触控上下文录入、分类、筛选、编辑、删除确认/取消、草稿返回、失败保留；同时点击保存，以及真实 API 已提交但响应丢失后的重试。
- 清晰日文票据真实 OCR、合计含税标签、日期与币种候选、人工核对确认、文字识别错误修正、疑似重复确认；商品/小计/税/找零不重复入账。
- 真实模型资源请求失败、真实空白图、取消/关闭/重开；模拟 Worker 单元测试验证超时、终止与晚到消息忽略。模拟 Worker 不用于验证识别准确率。
- 桌面和移动页面 Axe WCAG 检查没有 serious/critical 违规，移动页面没有横向溢出。

## 实际识别证据

清晰合成票据识别到 `合計 (税込) 1234円` 和 `2026年11月01日`。含逗号样例实际识别为 `合計 (税込) 1.234円`，界面提示日元小数可能是千位分隔符误识别，金额留空；测试人工改为 1234 后勾选确认。部分明细文字识别不准，因此不自动拆分商品，不将引擎置信度表述为字段准确率。

OCR 请求证据只含同站 worker/core/模型与本地 blob 预览；保存请求只有结构化消费字段，没有图片和 OCR 原文。图片不会上传给后端或第三方云服务。

E2E 默认将页面截图、合成日文票据、真实 OCR 文本和请求 URL 写到 `test-results/expense-evidence/`。运行日志、截图、录屏和交付清单属于本地产物，不随源码提交。保留证据时应同时记录用于测试的源码和锁文件指纹。

## 验证限制

OCR 是人工确认前的辅助输入，尚未在真实票据、真实手机硬件或独立 PostgreSQL 服务上验收。使用固定日英模型，仅保证本轮合成样例的实测结果。首次识别需下载同站模型/引擎；不支持 PDF/HEIC 或眼镜硬件输入。

后端依赖可能输出 Starlette/httpx 和 Alembic 配置弃用提示，需结合命令退出码判断测试结果。

## 隔离发布候选的验证

从已跟踪基线建立新的本地测试快照，只覆盖明确候选文件，不带入未提交的无关文档、真实数据库、环境文件或私人票据。使用固定锁文件安装依赖，并验证 Python 应用与前端构建根目录确实来自快照。

依次执行上表检查。迁移和恢复测试仅连接新建临时合成数据库；浏览器服务使用独占测试端口，禁止复用已有服务。记录候选文件和锁文件在测试前后的 SHA-256，测试后如有修改必须重新区分其范围并验证。未经精确目标和代码范围授权，不执行远端发布操作。
